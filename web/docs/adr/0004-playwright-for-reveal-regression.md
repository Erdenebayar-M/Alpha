# Playwright for the Reveal overshoot regression

`Reveal.tsx`'s scroll-triggered animations (`components/animations/Reveal.tsx`) had a bug where a fast scroll could carry a short, near-the-fold target (CategoryPills on `/landing-new`) from below its `IntersectionObserver` trigger line straight to fully above the viewport between two observer samples, so it never got marked visible and stayed at `opacity: 0` permanently. `web/AGENTS.md` says not to add a dependency unless a section genuinely needs one, and this repo had no test runner at all before this fix — but the bug only reproduces under real scroll-driven browser behavior (confirmed a plain `window.scrollTo` inside `page.evaluate` doesn't even trigger the observer callback in Chromium when the intersection ratio never leaves 0), which rules out a unit test. `@playwright/test` was added as a devDependency scoped narrowly to `e2e/reveal-overshoot.spec.ts`, covering only this regression; it is not wired into `.github/workflows/web-ci.yml` yet, so it doesn't run in CI and needs a separate decision before it does.

The same `hasScrolledPast` fallback was also added to `rise` mode for symmetry, but isn't covered by an automated test: its only current consumer, Pricing on `/`, is the last section on its page, so there's no scroll room to ever land "past" it, and forcing an artificial overshoot (an injected spacer, a forced viewport-resize recheck) triggered unrelated Chromium scroll-animation behavior rather than reproducing the real failure.
